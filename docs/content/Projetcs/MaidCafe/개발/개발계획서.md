[[기획서]]가 "무엇을 만드는가"(기능/사용자 흐름)를 다룬다면, 이
문서는 "그걸 어떤 기술/구조/알고리즘으로 구현했는가"를 다룹니다.
`docs/content/개발/개발계획서-상세/` 폴더에 12개 장으로 나눠 정리했고,
각 장은 다른 장을 몰라도 그 자체로 읽을 수 있게 썼습니다. **공부
목적으로 처음부터 순서대로 읽어도 되고, 필요한 장만 찾아 읽어도
됩니다.**

이 프로젝트는 포트폴리오용이라 실제 결제 게이트웨이(PG) 연동은 하지
않기로 확정했습니다 — 결제는 수단을 고르는 화면([[결제수단선택]])까지만
구현하고, 실제로 돈이 오가는 연동은 범위 밖입니다. 관리자 역할
구분/감사 로그도 같은 이유(매장 하나짜리 규모)로 만들지 않기로
했습니다([[관리자인증인가]] 참고).

## 주요 아키텍처 결정(ADR)
장 안에서 다루기엔 너무 근본적인 방향 결정은 `docs/decisions/`에
별도로 남깁니다.
- `docs/decisions/0001-kiosk-lock-screen-pinning.md` — 안드로이드
  키오스크 잠금을 Device Owner 완전 잠금 대신 Screen Pinning으로
  시작한 이유(iOS/아이패드의 동일 기능 비교 포함)
- `docs/decisions/0002-backend-분리-유지.md` — 백엔드를 Next.js API
  Route로 합치지 않고 Express로 독립 유지하는 이유(모바일 앱
  계획이 핵심 근거)

## 다음 우선순위 로드맵

아래 항목 중 실제 작업을 시작하는 항목은 `docs/AGENTS.md`의 SDD 워크플로우에

이 문서는 우선순위 개요만 담고, 항목별 상세 설계/작업 분해는 해당 스펙에
기록합니다.

1. **Tailwind 설정 정리** — 루트 `tailwind.config.ts`가 앱별 공용 설정
   패키지(`packages/config`) 없이 단독으로 존재합니다. 앱이 늘어나면
   통합을 검토합니다(낮은 우선순위로 보류 중).

## 완료 기준 (Definition of Done)

- `pnpm check-types`, `pnpm build`(또는 `turbo run check-types build`)가
  모두 통과할 것
- 백엔드 로직을 변경했다면 `pnpm --filter backend test`, 프론트엔드
  스토어(`features/cart` 등) 로직을 변경했다면 `pnpm --filter frontend
  test`가 통과할 것 — 이미 테스트가 있는 영역을 건드렸다면 해당
  테스트도 같이 갱신할 것
- 새/변경 파일에 `@owner: ai` 또는 `@owner: human` 태그가 붙어 있을 것
- 외부와 통신하는 함수(REST 호출, API 라우트)에는 TSDoc으로 무엇을
  주고받는지 명시할 것
- UI 변경은 실제 화면(dev 서버)에서 정상 동작을 확인할 것
