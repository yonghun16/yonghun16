## TL;DR
전부 **무료 티어로 운영 가능한 조합**을 골랐습니다: 프론트엔드는
Vercel, 백엔드는 Render, DB는 MongoDB Atlas, 이미지는 Cloudflare
R2. 유일한 무료 티어의 대가는 Render가 슬립한다는 것인데, 이건
오라클 클라우드의 무료 인스턴스에서 10분마다 핑을 보내 회피합니다.

## 서비스별 역할

| 서비스 | 무엇을 호스팅하는가 | 왜 이걸 골랐는가 |
|---|---|---|
| **Vercel** | `apps/frontend`(Next.js) | Next.js를 만든 회사의 배포 플랫폼이라 App Router 기능(이미지 최적화, `rewrites` 등)과 마찰이 없음. `main` 브랜치 push마다 자동 배포 |
| **Render** | `apps/backend`(Express) | 무료 티어에서 Node.js 웹 서비스를 상시 호스팅 가능(단, 슬립 있음). `main` push마다 자동 배포 |
| **MongoDB Atlas** | 상품/카테고리/주문/광고/세션/푸시구독 전체 | 관리형 MongoDB 무료 티어(M0) — 백업/모니터링을 직접 구축할 필요 없음 |
| **Cloudflare R2** | 상품/광고 이미지 원본(재인코딩된 WebP) | 이그레스(다운로드) 비용이 없는 S3 호환 오브젝트 스토리지 — [[06-이미지-파이프라인]] 참고 |
| **오라클 클라우드(Always Free)** | Render 헬스체크 크론 하나만 | 아래 "슬립 방지" 절 참고 |
| **GitHub Actions** | CI(품질 게이트) + `docs/`(Quartz 문서 사이트)를 GitHub Pages로 배포 | 앱 자체의 배포는 Vercel/Render가 각자 알아서 하므로, GitHub Actions는 **문서 사이트 배포 전용**입니다 — 헷갈리기 쉬운 부분이라 명시합니다 |

## Render 무료 티어 슬립과 헬스체크

Render의 무료 웹 서비스는 일정 시간(통상 15분) 요청이 없으면
프로세스를 잠재웁니다. 다음 요청이 오면 다시 깨우는데, 이 "콜드
스타트" 동안 첫 요청이 몇~몇십 초 지연됩니다 — 실제 손님이 주문을
누르는 순간 이 지연이 발생하면 안 됩니다.

```
GET /health  →  { status: 'ok' }   (DB 접근 없이 즉시 응답, 가장 가벼운 엔드포인트)
```

`app.ts`의 `/health`는 DB 조회를 하지 않는 가장 가벼운 엔드포인트로
만들어뒀고, **오라클 클라우드의 Always Free 인스턴스**에서 크론으로
10분마다(Render의 슬립 임계 시간보다 짧은 주기로) 이 엔드포인트를
호출합니다. 이러면 백엔드가 절대 슬립 임계 시간에 도달하지 않아,
실제 손님이 접근할 때는 항상 이미 깨어있는 상태입니다. 별도의 유료
"슬립 없음" 플랜을 쓰지 않고도 무료 티어 두 개(Render + 오라클
클라우드)를 조합해 상시 가동을 흉내내는 구성입니다.

Render 자체도 내부적으로 `/health` 같은 경로에 자체 헬스체크를
돌리지만(배포 성공 여부 판단용), 이건 슬립 방지 목적의 외부 핑과는
별개입니다 — 같은 엔드포인트를 두 가지 목적으로 겸용합니다.

## 환경변수 — 어디에 무엇이 있는가

| 환경변수 | 어디서 쓰는가 | 비고 |
|---|---|---|
| `MONGO_URI` | 백엔드 — 운영 DB 연결 | Atlas 연결 문자열 |
| `ADMIN_PASSWORD` | 백엔드 — 관리자 로그인 | [[04-인증과-세션]] |
| `SESSION_SECRET` | 백엔드 — 세션 쿠키 서명 | 없으면 재시작마다 로그인이 풀림(경고 로그) |
| `FRONTEND_ORIGIN` | 백엔드 — CORS 허용 오리진 | Vercel 배포 주소 |
| `R2_ENDPOINT`/`R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY`/`R2_BUCKET_NAME`/`R2_PUBLIC_URL` | 백엔드 — 이미지 업로드 | [[06-이미지-파이프라인]], 없으면 서버가 아예 안 뜸 |
| `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`/`VAPID_SUBJECT` | 백엔드 — 웹 푸시 | [[07-실시간-알림-아키텍처]], 없으면 알림 기능만 조용히 비활성화(서버는 뜸) |
| `BACKEND_ORIGIN` | 프론트엔드 — `rewrites()` 대상 | **빌드 시점**에 고정됨(1장 참고), 없으면 `NODE_ENV=production`일 때 Render 기본 주소로 폴백 |

두 실패 모드의 차이가 의도적입니다: R2 환경변수는 없으면 서버
기동 자체를 막습니다(이미지 업로드가 핵심 기능이라 조용히 실패하면
안 됨). VAPID 환경변수는 없어도 서버는 정상적으로 뜨고 알림
기능만 꺼집니다(알림은 부가 기능이라, 이것 때문에 전체 서비스가
멈추면 안 됨) — 이 판단 기준은 [[05-주문-핵심-알고리즘]]의
"fire-and-forget" 절에서 설명한 "핵심 기능 vs 부가 기능의 실패
허용 범위" 원칙과 같습니다.

## 프론트엔드 이미지 최적화 허용 목록

```js
images: { remotePatterns: [{ protocol: 'https', hostname: '*.r2.dev' }] },
```

`next/image`는 외부 도메인 이미지를 최적화하려면 허용 목록에 등록해야
합니다. R2 공개 버킷 주소(`pub-<해시>.r2.dev`)는 버킷을 새로 만들면
해시가 바뀔 수 있어 서브도메인을 와일드카드로 등록해뒀습니다.

## 문서 사이트(GitHub Pages)는 별도 파이프라인
`docs/` 폴더는 Quartz 5로 만든 Obsidian Vault 정적 사이트입니다 —
지금 읽고 있는 이 문서를 포함한 모든 Vault 문서가 여기서
빌드됩니다. `.github/workflows/deploy.yml`이 `main` push마다
`docs/`에서 `npx quartz build`를 실행해 GitHub Pages로 배포합니다.
이건 **애플리케이션(프론트엔드/백엔드) 배포와는 완전히 무관한
별도 파이프라인**입니다 — 이름이 비슷해 헷갈리기 쉬워 명시적으로
구분해둡니다. 애플리케이션 배포는 Vercel/Render가 각자 GitHub
연동으로 `main` push를 감지해 자체적으로 처리하므로, 이 저장소의
GitHub Actions에는 앱 배포 스텝이 없습니다.
