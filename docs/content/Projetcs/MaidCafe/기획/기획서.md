메이드 카페 매장에서 고객이 직접 메뉴를 조회·주문하고, 매장 관리자가 메뉴를
등록·삭제할 수 있는 무인 키오스크 서비스입니다. 고객 주문 흐름과 관리자
메뉴 관리 흐름, 관리자 로그인까지 핵심 기능은 구현되어 있습니다. **포트폴리오
프로젝트**라 결제 수단을 고르는 화면([[결제수단선택]])까지만 만들고, 실제
PG사와 연동해 돈이 오가는 결제 게이트웨이 연동은 처음부터 범위에 넣지
않았습니다.

## 배경 및 목적

카페 사장님과 고객 모두를 위한 키오스크 서비스입니다. 고객은 매장 내
키오스크(또는 화면)에서 메뉴를 둘러보고 주문을 담아 제출하고, 매장 관리자는
별도의 관리자 화면에서 실시간으로 메뉴를 추가·삭제합니다.

## 사용자

### 고객
- 매장에 방문해 키오스크 화면(`/`)에서 메뉴를 탐색하고 주문하는 사람.
- 별도 로그인 없이 바로 이용합니다.

### 매장 관리자
- 관리자 화면(`/admin`)에서 메뉴(상품)를 등록·삭제하는 매장 운영자.
  들어온 주문 확인/완료 처리는 별도 주방 화면(`/kitchen`)에서 합니다
  (같은 로그인 세션 공유, 화면만 분리).
- 공유 비밀번호로 로그인해야 접근할 수 있습니다([[관리자로그인인증]]
  참고). 점주/직원 등 역할 구분은 아직 없습니다.

## 핵심 사용자 흐름

### 고객: 메뉴 조회 → 주문
1. 키오스크 첫 화면(`/`)에서 매장에서 먹을지 포장할지 먼저 선택합니다
   ([[매장내포장선택]]). 선택해야 메뉴 목록으로 넘어갑니다. 이 화면
   아래에는 관리자가 등록한 광고 배너가 자동으로 전환되며 나타납니다
   ([[광고관리]]).
2. 관리자가 등록한 카테고리별로 메뉴를 필터링합니다(첫 카테고리가 기본
   선택됨 — "전체" 옵션은 없음, [[카테고리별메뉴조회]] 참고).
3. 원하는 메뉴 카드를 클릭하면 옵션 선택 모달이 뜹니다. 매장 전체
   고정 옵션은 없고, 관리자가 그 메뉴에 설정해둔 옵션만 나타납니다 —
   "온도(HOT/ICE)"/"마법의 주문"은 켜져 있으면 콤보박스(하나만 선택),
   "샷 추가" 등 그 외 옵션은 등록돼 있으면 체크박스(여러 개 동시
   선택)로 표시됩니다([[옵션조합관리]] 참고). "담기"를 누르면
   장바구니에 담기고, 같은 메뉴를 같은 옵션 조합으로 다시 담으면
   수량이 1 증가합니다.
4. 화면 오른쪽 주문 목록에서 담긴 메뉴와 총 금액을 확인하고, 항목별
   +/- 버튼으로 수량을 조절하거나 삭제 버튼으로 항목을 뺄 수 있습니다.
5. "주문하기"를 누르면 결제 수단(신용카드/NPay/Kakao Pay/토스페이)을
   고르는 모달이 뜨고, 하나를 누르면 매장/포장 선택값과 고른 결제
   수단이 함께 주문 서버에 제출됩니다. 성공 시 장바구니가 비워지고
   주문번호와 예상 대기 시간을 안내하는 화면이 뜹니다([[주문완료화면]]
   참고) — "확인"을 누르거나 8초 뒤 자동으로 닫히면 다음 손님을 위해
   1번 선택 화면으로 돌아갑니다. 실패하면 안내 메시지만 뜨고 장바구니
   내용은 유지됩니다. 실제 결제 게이트웨이 연동은 아직 없어([[결제수단선택]]
   참고), 고른 수단은 기록만 됩니다.

### 관리자: 메뉴 관리
1. 관리자 화면(`/admin`)에 접속하면 먼저 로그인 폼이 뜨고, 공유
   비밀번호를 입력해야 이후 화면을 쓸 수 있습니다([[관리자로그인인증]]).
2. 로그인 후 메뉴 이름·가격·이미지(파일 업로드)·카테고리를 입력해 새
   메뉴를 등록합니다. 이미지 파일을 선택하면 서버에 업로드되고 반환된
   URL이 자동으로 채워집니다. 이 메뉴에서만 고를 수 있는 옵션(이름 +
   추가금)도 원하는 만큼 추가할 수 있습니다([[옵션조합관리]] 참고).
3. 필수 항목이 비어 있으면 안내 메시지가 뜨고 제출되지 않습니다.
4. 등록에 성공하면 폼이 초기화되고 메뉴 목록에 즉시 반영됩니다. 실패하면
   폼 입력값은 유지된 채 에러 메시지만 뜹니다.
5. 메뉴 목록에서 "삭제"를 누르면 확인창을 거쳐 메뉴가 삭제됩니다.

## 기능 요구사항

### 고객 화면 (`/`)
- 매장 내(Dine-in) / 포장(Takeout) 선택 (메뉴 조회 전 필수)
- 메뉴 목록 조회 (카테고리 필터 — 관리자가 등록한 카테고리 목록, 첫
  카테고리 기본 선택. "전체" 옵션 없음)
- 품절 메뉴 표시 (흑백 처리 + 배지, 장바구니 담기 불가)
- 메뉴 클릭 시 옵션 선택 모달 → "담기"로 장바구니에 추가. 매장 전체
  고정 옵션은 없고, 관리자가 메뉴마다 설정한 것만 표시됩니다: (1)
  "온도" — 관리자가 "없음/HOT+ICE/HOT만/ICE만" 중 골라두면, HOT+ICE인
  메뉴만 고객이 하나를 고르는 콤보박스로 뜨고 HOT만/ICE만로 고정된
  메뉴는 고를 것 없이 그 값이 자동으로 담김(카레는 HOT만, 에이드는
  ICE만처럼), (2) "마법의 주문"(모에모에뀽 등) — 관리자가 체크박스로
  켜면 고객 화면엔 하나만 고르는 콤보박스로 노출, (3) 그 외 옵션(이름
  + 추가금, 예: "샷 추가") — 관리자가 등록하면 체크박스로 노출되고
  여러 개 동시 선택 가능([[옵션조합관리]] 참고). 같은 메뉴도 옵션
  조합이 다르면 장바구니에서 별도 줄로 취급
- 장바구니 담기 / 수량 자동 증가(같은 메뉴+같은 옵션일 때만 병합)
- 장바구니 항목별 수량 조절(+/-) / 삭제
- 장바구니 총액 계산
- 결제 수단 선택 모달(신용카드/NPay/Kakao Pay/토스페이 중 하나 고르면
  바로 주문 제출, 실제 결제 처리는 없고 선택값만 기록, [[결제수단선택]]
  참고)
- 주문 제출, 제출 중 로딩 상태 표시
- 주문 완료 화면 (주문번호 + 예상 대기 시간 안내, "확인" 또는 8초
  자동 닫힘으로 매장/포장 선택 화면 복귀, [[주문완료화면]] 참고)
- 첫 화면(매장/포장 선택 화면)에 광고 배너 표시 (관리자가 정한 순서로
  자동 전환, 0개면 미표시)
- 세션 타임아웃 (매장/포장을 고른 뒤 1분간 조작이 없으면 경고 없이
  장바구니를 비우고 매장/포장 선택 화면으로 복귀, [[세션타임아웃]]
  참고)
- PWA로 홈 화면에 설치 가능 (안드로이드/데스크탑은 설치, iOS는 홈 화면
  추가, 아이콘 실행 시 이 화면부터 열림, [[PWA설치]] 참고)

### 관리자 화면 (`/admin`)
- 로그인/로그아웃 (공유 비밀번호 기반 세션)
- 메뉴 등록 (이름, 가격, 이미지 파일 업로드, 카테고리, 온도/마법의
  주문 콤보박스 옵션 체크박스, 메뉴 옵션 — 이름+추가금 여러 개 등록
  가능)
- 메뉴 목록 조회
- 메뉴 수정 (이름, 가격, 이미지, 카테고리, 온도/마법의 주문 콤보박스
  옵션, 메뉴 옵션)
- 메뉴 순서 변경 (같은 카테고리 안에서 드래그 또는 ▲▼ 버튼, 고객
  화면 메뉴 목록에도 반영)
- 품절 처리 / 판매 재개
- 재고 수량 관리 (선택 — 설정한 메뉴만 주문마다 자동 차감, 소진 시
  자동 품절, ＋/－ 버튼으로 수동 조정)
- 메뉴 삭제 (삭제 전 확인)
- 카테고리 추가/수정/삭제 (삭제 시 소속 메뉴도 함께 삭제, 확인 필요)
- 카테고리 순서 변경 (드래그 또는 ◀▶ 버튼, 고객 화면 필터에도 반영)
- 광고 배너 추가/수정/삭제 (첫 화면에 노출)
- 광고 배너 순서 변경 (드래그 또는 ◀▶ 버튼)
- 판매 통계 조회 (최근 6개월 월별 판매량/매출 추이 차트, 선택한 달의
  메뉴별 판매 순위)

### 주방 화면 (`/kitchen`)
메뉴/광고/통계 관리와 섞이면 주문만 계속 지켜봐야 하는 주방/카운터
직원 입장에서 산만해서, 관리자 화면에서 분리한 전용 화면입니다.
로그인 세션은 `/admin`과 동일한 공유 비밀번호 기반 세션을 그대로
쓰고(권한 분리는 없음), 두 화면은 헤더의 링크로 서로 오갈 수 있습니다.
- 로그인/로그아웃 (`/admin`과 세션 공유)
- 주문 내역 조회 (최신순, 10초 자동 갱신 + 수동 새로고침, 날짜/매장·
  포장 필터)
- 주문 완료 처리 (완료 시 진행중 → 완료한 주문 탭으로 이동)

## 데이터 모델 개요

- **상품(Product)**: 이름, 가격, 이미지 URL, 카테고리(자유 입력 —
  아래 카테고리(Category) 참고), 순서(`order`, 같은 카테고리 안에서
  작을수록 먼저 표시), 품절 여부(`isSoldOut`, 기본값 false), 재고
  수량(`stock`, 선택 필드 — 없으면 재고 추적 안 함, [[재고관리]] 참고),
  옵션 목록(`options`, 선택 필드 — 이름+추가금 배열, 관리자가 메뉴별로
  자유롭게 등록), 온도 콤보박스 옵션(`temperatureOption`, 선택 필드 —
  `'BOTH' | 'HOT' | 'ICE'`, 없으면 온도 옵션 자체가 없는 메뉴), 마법의
  주문 콤보박스 옵션 노출 여부(`hasMagicSpellOption`, 선택 필드,
  [[옵션조합관리]] 참고)
- **카테고리(Category)**: 이름(`name`), 순서(`order`, 작을수록 먼저
  표시). 관리자가 자유롭게 추가·수정·삭제·순서 변경 가능. 상품은
  카테고리를 id가 아니라 이름으로 참조하므로, 이름을 수정하면 그
  카테고리의 상품도 함께 갱신되고, 삭제하면 상품도 함께 삭제됩니다
  ([[카테고리관리]] 참고)
- **장바구니 아이템(CartItem)**: 상품 정보 + 수량 + 콤보박스 옵션
  선택값(`temperature`, `magicSpell`) + 메뉴 옵션 중 고른 것들의
  스냅샷(`selectedOptions`) + 장바구니 전용 구분 id(`cartItemId` —
  같은 상품도 옵션 조합이 다르면 다른 줄로 취급). 클라이언트 상태로만
  존재하고 서버에 저장되지 않습니다([[옵션조합관리]] 참고).
- **주문(Order)**: 주문 아이템 목록(상품 id, 이름, 가격 — 옵션 추가금
  포함된 최종 단가, 수량, 옵션 선택 여부, `selectedOptions`) + 총액 +
  매장 내/포장 구분(`orderType`) + 결제 수단(`paymentMethod`, 선택
  필드 — 실제 결제 처리 없이 고른 값만 기록, [[결제수단선택]] 참고) +
  생성 시각.
- **광고(Ad)**: 이미지 URL, 순서(`order`, 작을수록 먼저 표시), 등록
  시각(`createdAt`). 관리자가 드래그 또는 ◀▶ 버튼으로 순서를 바꿀 수
  있습니다([[광고관리]] 참고).

모든 타입은 `packages/types`에서 프론트엔드·백엔드가 함께 정의를
공유합니다.

## 일반 키오스크 기능 청사진 (참고용)

일반적인 무인 주문 키오스크 시스템이 보통 갖추는 기능을 프론트엔드/관리자
/백엔드로 나눠 정리한 청사진입니다. 각 기능은 **완료/작업중/작업전** 3단계로
진행 상태를 표시합니다. **전부 다 만들겠다는 확정 목록이 아니라, 향후 범위를
논의할 때 빠뜨리기 쉬운 항목을 확인하는 체크리스트**입니다. 실제 작업
우선순위는 [[개발계획서]]의 로드맵에서 정합니다. 각 기능의 상세 설명은
`기획/기능/` 하위의 개별 문서를 참고하세요.

이 프로젝트는 **포트폴리오용**이라, 실제 결제·다중 매장 운영·회원제
같은 실사업 전제가 있어야 의미 있는 기능들(실제 PG 결제 게이트웨이,
영수증/주방 프린터 등 물리 하드웨어 연동, 멤버십·쿠폰 시스템, 다중
매장/다중 키오스크 운영, 오프라인 대응, 모니터링/로깅 인프라 등)과
지금 범위에서 우선순위가 낮다고 판단한 부가 기능들(미조작 시 홍보
슬라이드를 보여주는 대기 화면과 그 배너 관리, 다국어 지원, 메뉴 검색,
추천/세트 메뉴, 접근성 대응, 숨김 제스처로 관리자 모드 진입)은 처음부터
청사진에서 뺐습니다. 실제 매장에 배포해 운영할 일이 생기거나 시연에
필요해지면 그때 다시 검토합니다.

## 알려진 제약 / 리스크

- 관리자 로그인은 계정별이 아니라 공유 비밀번호 하나로 세션을 발급하는
  방식입니다([[관리자로그인인증]]). 점주/직원 역할 구분, 감사 로그는
  매장 하나짜리 포트폴리오 규모에는 실익이 없다고 판단해 만들지
  않기로 확정했습니다([[관리자인증인가]] 참고) — 결제 게이트웨이와
  같은 종류의 스케일 판단입니다.
- 결제 수단 선택 화면은 있지만 실제 결제 게이트웨이 연동은 없습니다
  ([[결제수단선택]] 참고) — 포트폴리오 프로젝트라 처음부터 범위 밖으로
  정했습니다. 어떤 수단을 선택해도 실제로 돈이 오가지 않고 고른 값만
  기록됩니다.
