## 개요
카테고리(`coffee`|`ade`|`dessert`)가 코드에 고정된 enum이던 것을 관리자
화면에서 직접 추가·수정·삭제할 수 있는 동적 데이터로 전환했습니다.
별도 탭이 아니라 **`/admin`의 "메뉴 관리" 탭 안에 카테고리 칩 바**로
들어가 있습니다 — 칩을 클릭하면 그 카테고리의 메뉴만 필터링되고, 칩을
드래그하거나 붙어있는 ✎(수정)/✕(삭제) 버튼으로 바로 관리합니다.

## 동작 방식
`Category` 컬렉션(`{ name }`)이 카테고리 목록의 원본입니다. `Product.category`는
Category의 id가 아니라 **이름 문자열을 그대로 참조**합니다 — 그래서:
- **카테고리 이름을 수정**하면(`PUT /api/categories/:id`) 그 이름을 쓰던
  모든 상품의 `category` 필드도 새 이름으로 함께 갱신됩니다
  (`Product.updateMany`).
- **카테고리를 삭제**하면(`DELETE /api/categories/:id`) 그 카테고리에
  속한 상품이 전부 함께 삭제됩니다(`Product.deleteMany`). 관리자 화면에서
  삭제 전 "소속 메뉴도 함께 삭제됩니다" 확인창을 거칩니다.

기존에 고정 enum으로 저장돼 있던 상품 데이터(`coffee`/`ade`/`dessert`)를
별도로 마이그레이션하지 않기 위해, 백엔드가 시작할 때 `Category` 컬렉션이
비어 있으면 `Product.distinct('category')`로 이미 쓰이고 있는 카테고리
값들을 자동으로 채워 넣습니다(`ensureDefaultCategories`, 1회성·멱등).
그래서 기존 상품이 가리키던 카테고리 이름이 그대로 카테고리 목록에
나타나며, 관리자가 이후 원하는 이름으로 수정하면 됩니다.

카테고리가 완전히 자유 입력이 되면서, 상품 카드의 카테고리별 고정
색상(커피=주황, 에이드=초록 등)은 의미가 없어져 하나의 통일된 스타일로
단순화했습니다.

**순서 변경**: 각 카테고리는 `order`(숫자) 필드를 가지며, 값이 작을수록
앞에 표시됩니다. 칩 앞의 손잡이(⠿)를 **눌러서 드래그**하면 순서가
바뀝니다. 처음엔 브라우저 네이티브 HTML5 드래그 앤 드롭(`draggable`
속성)으로 구현했는데, 칩 안에 버튼이 여러 개 겹쳐 있으면 드래그 시작
자체가 인식되지 않는 경우가 있어(브라우저/기기별로 제각각이고, 특히
터치 기기는 애초에 native HTML5 DnD를 지원하지 않음) 실사용에서
"드래그가 안 된다"는 문제로 이어졌습니다. 그래서 **포인터 이벤트
(mouse/touch/pen 통합) 기반 커스텀 드래그**로 다시 구현했습니다 —
전용 손잡이에서 `pointerdown`으로 드래그를 시작하고, `window`의
`pointermove`로 어느 칩 위에 있는지 좌표 hit-test해 화면 순서만 즉시
바꾸다가(`reorderLocally`, API 호출 없음), `pointerup`에서 한 번만
서버에 저장합니다(`commitCategoryOrder`). 별도 라이브러리 없이
구현했습니다.

처음엔 ◀▶ 버튼도 드래그의 대안으로 함께 뒀는데, "드래그만으로
충분하다"는 판단에 따라 **버튼은 뺐습니다**(메뉴 순서 변경의 ▲▼
버튼은 이 결정과 무관하게 그대로 유지 — [[메뉴수정품절처리]] 참고).
`moveCategory`/`moveCategoryToIndex` 액션도 버튼과 함께 제거했습니다.

`PATCH /api/categories/reorder`가 원하는 순서로 나열한 카테고리 id
배열을 통째로 받아 배열 인덱스를 그대로 `order` 값으로 저장합니다. 새
카테고리는 항상 맨 뒤 순서로 추가됩니다. 이 순서는 고객 화면의 카테고리
필터, 관리자 화면의 메뉴 등록/수정 폼의 카테고리 목록에도 그대로
반영됩니다(전부 서버가 내려주는 순서를 그대로 씀). `order` 필드가 생기기
전에 이미 있던 카테고리는 서버 시작 시 이름순으로 순서를 자동
부여합니다(`ensureCategoryOrder`, 1회성·멱등).

**메뉴 목록과의 연동**: 칩을 클릭해 고른 카테고리는 `AdminPage`가
`selectedCategory` 상태로 들고 있다가 `ManageProductList`에 그대로
전달되어, 그 카테고리에 속한 메뉴만 걸러서 보여줍니다("전체" 칩을
누르면 다시 전체가 보임). 선택된 카테고리의 이름을 수정하면 필터도 새
이름으로 따라가고, 선택된 카테고리를 삭제하면 필터가 자동으로 "전체"로
돌아갑니다.

### 관련 코드
- `apps/backend/src/models/Category.ts` (`name`, `order` 필드, `name`
  unique 인덱스)
- `apps/backend/src/models/Product.ts` (`category`에서 고정 `enum` 제거)
- `apps/backend/src/routes/categories.ts` — `GET/POST /api/categories`,
  `PUT/DELETE /api/categories/:id`, `PATCH /api/categories/reorder`
  (`requireAdmin`으로 보호, `GET`만 공개)
- `apps/backend/src/lib/seed.ts` — `ensureDefaultCategories`/
  `ensureCategoryOrder`(자동 시딩)
- `apps/frontend/src/entities/category` (`getCategories`, `createCategory`,
  `updateCategory`, `deleteCategoryById`, `reorderCategories`)
- `apps/frontend/src/features/category-management/model/store.ts`
  (`useCategoryStore`, `reorderLocally`/`commitCategoryOrder`가 포인터
  드래그용 로컬 재배치/저장 분리 — 버튼 액션 없음)
- `apps/frontend/src/widgets/manage-category-list/ui/ManageCategoryList.tsx`
  (카테고리 칩 바 — 클릭 시 필터, 추가/인라인 수정/삭제, 포인터 이벤트
  기반 드래그 앤 드롭. 순서 변경 버튼 없음)
- `apps/frontend/src/views/admin/ui/AdminPage.tsx` ("메뉴 관리" 탭 안에
  칩 바를 얹고, 선택된 카테고리를 `ManageProductList`와 공유)
- `apps/frontend/src/widgets/manage-product-list/ui/ManageProductList.tsx`
  (`selectedCategory` prop으로 메뉴 목록 필터링)
- `apps/frontend/src/widgets/add-product-form`,
  `manage-product-list/ui/EditProductForm.tsx` (카테고리 select를 하드코딩
  대신 동적 목록으로 교체)
- `apps/frontend/src/widgets/product-list/ui/ProductList.tsx` (고객 화면
  카테고리 필터도 동적 목록으로 교체)
- `apps/frontend/src/entities/product/ui/ProductCard.tsx` (카테고리별
  고정 색상 제거, 통일된 스타일로 단순화)
- `packages/types`의 `Category`(`order` 필드), `CategoryInput`,
  `ReorderCategoriesInput`, `Product.category`(고정 union → `string`)
