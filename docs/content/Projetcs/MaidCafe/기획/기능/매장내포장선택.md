## 개요
키오스크(`/`)에 처음 들어오면 메뉴 목록 대신 "매장에서 드시나요 포장해
드릴까요?" 선택 화면이 먼저 뜹니다. 선택해야만 메뉴 목록으로 넘어갈 수
있고, 선택한 값은 주문에 그대로 포함됩니다.

## 동작 방식
`features/order-type`의 Zustand 스토어가 `orderType`(`'dine-in' |
'takeout'` | `null`)을 들고 있습니다. `orderType`이 `null`이면
`HomePage`가 메뉴 목록 대신 `OrderTypeSelect` 화면을 보여주고, "매장에서"
또는 "포장" 버튼을 누르면 값이 채워지며 메뉴 목록(`ProductList` +
`OrderSummary`)으로 전환됩니다. 주문 목록 패널에는 현재 선택이 작게
표시됩니다. "주문하기"를 눌러 주문이 성공하면 [[주문완료화면]]이 먼저
뜨고, 그 화면을 닫을 때(확인 클릭 또는 8초 자동 닫힘) 다음 손님을 위해
`orderType`이 다시 `null`로 초기화되어 선택 화면으로 돌아갑니다 — 주문
성공 직후 바로 초기화하지 않는 이유도 [[주문완료화면]] 참고. 선택값은
`POST /api/orders` 요청의 `orderType` 필드로 함께 전송되어 주문
데이터에 저장됩니다.

매장 내 선택 시 테이블 번호를 받는 흐름은 필요 없다고 판단해 백로그에서
제외했습니다.

**중간에 매장/포장을 바꾸는 기능**: 손님이 메뉴를 고르다가 매장↔포장을
바꾸고 싶을 수 있는데, 처음엔 주문을 완료해야만(또는 새로고침해야만)
선택 화면으로 돌아갈 수 있었습니다. "중간에 처음 화면으로 돌아가는
버튼이 필요할 것 같다"는 요청으로 화면 상단에 버튼을 추가했고, 이후
두 차례 더 다듬었습니다.

1차: `HomePage` 최상단에 현재 선택("🍽️ 매장에서 주문 중"/"🥡 포장
주문 중")과 큰 "↩ 처음으로" 버튼을 항상 띄움 — 눌러도 `orderType`만
`null`로 초기화될 뿐 장바구니(`features/cart`)는 그대로 남아있어서,
다시 매장/포장을 고르면 담아둔 메뉴가 그대로 이어짐.

2차: "키오스크에 어울리는 위치인지" 피드백으로, 페이지 문서 흐름 안에
있던 버튼이 메뉴 목록을 스크롤하면 화면 밖으로 같이 사라지던 문제를
`fixed inset-x-0 top-0 z-40` 상단 고정 바로 해결. 콘텐츠가 가려지지
않도록 `ProductList`+`OrderSummary`를 감싸는 컨테이너에
`pt-20`(모바일)/`pt-24`(데스크탑) 여백 추가.

3차(현재): 일반적인 키오스크는 매장/포장을 상단에 크게 노출하지 않고
작은 배지로 줄여 표시한다는 사용자 제안을 판단 후 일부만 채택
(하단 재배치나 이전/처음으로/다시하기 세분화는 이 앱의 단일 화면
구조에 과하다고 보고 제외). 상단 고정 바의 큰 버튼을 작은 배지
("🍽️ 매장에서 ▾")로 줄이고, 누르면 `Modal`로 "매장식사/포장"을
라디오로 고르는 팝업이 뜹니다. 이 팝업의 "변경" 버튼은 장바구니를
건드리지 않는 비파괴적 동작이라 확인 없이 바로 `setOrderType`을
호출합니다. 팝업 안의 "↩ 처음부터 다시 시작" 링크를 누르면 별도의
확인 팝업("계속 주문" / "처음으로")을 한 번 더 거친 뒤에야
`resetOrderType`이 호출됩니다 — 실수로 눌러 화면이 선택 화면으로
튕기는 걸 막기 위함입니다(장바구니 자체는 이 경로로도 지워지지
않습니다).

## 모바일 앱(`apps/mobile`) 포팅

웹의 3차 배지+팝업 구조를 그대로 React Native로 옮겼습니다. 헤더의
매장/포장 표시를 `Text`에서 `Pressable`로 바꾸고, `shared/ui/Modal`
기반의 두 팝업(주문 방식 라디오 선택, 처음으로 확인)을 추가했습니다.
구현 중 배지에 테두리/패딩이 생기며 폭이 넓어져 헤더의 "🎀 Maid Kiosk"
로고 텍스트가 잘리는 부수 버그를 발견해, 로고엔 `shrink` +
`numberOfLines={1}`, 배지엔 `shrink-0`을 줘서 함께 고쳤습니다.

## 관련 코드
- `apps/frontend/src/features/order-type` (`useOrderTypeStore` —
  `setOrderType`으로 즉시 전환, `resetOrderType`으로 선택 화면 복귀)
- `apps/frontend/src/widgets/order-type-select/ui/OrderTypeSelect.tsx`
- `apps/frontend/src/views/home/ui/HomePage.tsx` (선택 전/후 화면 전환,
  상단 고정 바의 매장/포장 배지 → 변경 팝업(`Modal`, 라디오 선택) →
  "처음부터 다시 시작" 확인 팝업(`Modal`) 순으로 연결)
- `apps/frontend/src/shared/ui/Modal.tsx` (변경/확인 팝업 둘 다 재사용)
- `apps/frontend/src/widgets/order-summary/ui/OrderSummary.tsx`
  (선택값 표시)
- `apps/frontend/src/widgets/order-complete/ui/OrderCompleteScreen.tsx`,
  `apps/frontend/src/views/home/ui/HomePage.tsx` (주문 성공 후
  `orderType` 초기화는 이 화면을 닫을 때 일어남, [[주문완료화면]] 참고)
- `apps/frontend/src/features/cart/model/store.ts` (`submitOrder`가
  `orderType`을 받아 요청에 포함)
- `apps/backend/src/models/Order.ts` (`orderType` 필드),
  `apps/backend/src/routes/orders.ts` — `POST /api/orders`
- `packages/types`의 `OrderType`, `Order`, `CreateOrderInput`
- `apps/mobile/src/views/home/ui/HomePage.tsx` (배지 `Pressable` + 변경/
  처음으로 팝업)
- `apps/mobile/src/shared/ui/Modal.tsx` (RN `Modal` 기반 팝업 재사용)
