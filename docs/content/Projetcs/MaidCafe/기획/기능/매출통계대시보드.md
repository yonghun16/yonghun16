## 개요
매장 운영 의사결정을 돕기 위해 매출 추이와 인기 메뉴를 보여주는
대시보드입니다. "조회할 지표 범위"가 열린 질문이었는데, **연도별 월간
추이 그래프 + 선택한 달의 메뉴별 판매 순위**로 범위를 정했습니다(일별
집계, 카테고리별 집계 등은 이번 범위에 넣지 않음). 관리자 화면은 주로
PC에서 쓴다는 전제([[주문내역조회]] 참고)에 맞춰 그래프/목록 모두 넓은
화면에서 잘 보이도록 데스크탑 위주로 만들었습니다.

## 동작 방식
- `/admin`의 **"판매 통계" 탭**에 두 블록이 있습니다.
  1. **월별 판매량 추이**: 연도 선택 버튼(올해~4년 전, 5개)으로 고른
     해의 1~12월 판매량을 **꺾은선 그래프**로 보여줍니다. 각 점 위에
     그 달의 판매량 숫자를, 아래에 몇 월인지 라벨을 표시합니다. 처음엔
     막대 그래프였는데 꺾은선으로 바꿨습니다. 주문이 없는 달도 0으로
     채워 넣어 항상 12개 점이 이어집니다.
  2. **메뉴별 판매 순위**: 그래프의 점(또는 아래 월 라벨)을 클릭해 고른
     달의 메뉴별 판매량/매출 순위 목록입니다(판매량 내림차순). 데스크탑
     화면에서는 2~3열 그리드로 넓게 배치됩니다. 목록 위에는 그 달의
     총 판매량·매출 합계도 함께 표시합니다. 연도를 바꾸면 그 해에서
     판매 기록이 있는 가장 최근 달이 자동으로 선택되고, 기록이 아예
     없으면 12월이 기본 선택됩니다.
- **연도 필터**: `GET /api/orders/stats/monthly?year=YYYY`가 그 해
  1~12월 12개월치를 반환합니다(과거엔 "최근 N개월" 방식이었는데
  연도 선택 방식으로 바꿈). 프론트의 연도 버튼은 오늘 날짜 기준
  올해부터 4년 전까지 고정 5개를 보여줍니다(실제 주문 데이터가 있는
  연도만 걸러주는 별도 API는 없음 — 필요해지면 추가 검토).
- **집계 기준**: 주문 생성 시점(`Order.createdAt`)을 KST로 환산한
  연-월로 묶습니다. 완료 여부(`isCompleted`)와 무관하게 생성된 주문을
  판매로 집계합니다 — 완료 처리는 "주방에서 다 만들어 건넸다"는 뜻이라
  매출 집계와는 무관하기 때문입니다. 다만 **취소된 주문(`isCancelled:
  true`)은 집계에서 제외**합니다 — 취소는 실제로 이뤄지지 않은 판매라서
  입니다([[주문상태전이-API]] 참고).
- **성능**: 실시간 MongoDB 집계(`$group`/`$unwind`)로 매 요청마다
  계산합니다. 주문량이 아주 많아지면 사전 집계(별도 컬렉션에 배치로
  미리 합산)로 바꿀 수 있지만, 지금 규모(매장 1곳)에서는 실시간
  집계로 충분합니다.
- **그래프 구현**: 외부 차트 라이브러리 없이 SVG를 직접 그렸습니다
  (`viewBox` 기반이라 화면 너비에 맞춰 자동으로 늘어남). 판매량 값에
  따라 매번 달라지는 점 좌표는 Tailwind 유틸리티로 표현할 수 없어서
  좌표 계산 자체는 JS로, 점/선/라벨은 `<circle>`/`<polyline>`/`<text>`
  SVG 요소로 그렸습니다. 각 점은 실제 반지름보다 넓은 투명한 원을
  겹쳐서 클릭 영역을 넉넉하게 잡았습니다.
- **메뉴별 판매 순위의 이미지 폴백**: `OrderItem.imageUrl`은 주문 시점
  스냅샷인데, 이 필드가 상품/주문 코드에 나중에 추가돼서 그 이전에
  만들어진 옛 주문에는 값이 비어 있습니다(실제 운영 데이터로 확인해
  보니 대부분의 과거 주문이 여기 해당했습니다). 그대로 두면 순위표에
  이미지가 안 보여서, `imageUrl`이 없는 항목은 **지금 상품 정보의
  이미지로 대신 채웁니다**(상품이 그새 삭제됐으면 빈 문자열 → 프론트가
  회색 박스로 대체 표시). 처음 구현할 때 이 폴백 조회에서 집계 결과의
  `_id`(MongoDB `ObjectId`)를 문자열로 변환하지 않고 그대로 `Map` 키
  조회에 써서 항상 실패하는 버그가 있었고, `String(r._id)`로 바꿔서
  고쳤습니다.

## 관련 코드
- `packages/types`의 `MonthlySalesSummary`, `ProductSalesRanking`
- `apps/backend/src/routes/orders.ts` — `GET /api/orders/stats/monthly`
  (특정 연도의 1~12월 추이, 생략하면 올해, 없는 달은 0으로 채움),
  `GET /api/orders/stats/monthly/:month`(그 달의 메뉴별 판매 순위),
  둘 다 `requireAdmin`으로 보호
- `apps/backend/src/lib/date.ts` — `getKstYear`/`getMonthLabelsForYear`/
  `getKstMonthRange` 헬퍼(KST 기준 연/월 경계 계산,
  `getKstStartOfToday`와 같은 패턴)
- `apps/frontend/src/entities/order/api/orderApi.ts`
  (`getMonthlySalesSummary(year?)`, `getProductSalesRanking`)
- `apps/frontend/src/widgets/sales-dashboard/ui/SalesDashboard.tsx`
  (연도 선택 버튼 + SVG 꺾은선 그래프(`MonthlyLineChart`) + 순위
  그리드. `imageUrl`이 빈 문자열이면 회색 placeholder 박스로 대체)
- `apps/frontend/src/views/admin/ui/AdminPage.tsx` ("판매 통계" 탭)
