## 개요
고객 화면 첫 화면(매장/포장을 고르는 화면)에서 매장 브랜딩/홍보 효과를
놓치지 않도록, 관리자가 광고 배너 이미지를 직접 추가·수정·삭제할 수
있는 기능입니다. `/admin`의 **"광고 관리" 탭**에서 관리하고, 등록된
이미지가 고객 화면에 순서대로(등록순) 자동 전환되며 나타납니다.

일정 시간 미조작 시에만 나타나는 별도의 "대기 화면" 개념과는 다른
기능입니다(그런 미조작 대기 화면은 포트폴리오 범위 밖으로 정리했습니다,
[[세션타임아웃]] 참고) — 이 광고 배너는 미조작 대기 상태가 아니라
**항상 보이는 첫 화면에 곧바로** 나타납니다.

## 동작 방식
`Ad` 컬렉션(`{ imageUrl, order }`, `createdAt` 자동 생성)이 광고 목록의
원본이며, `order`(숫자, 작을수록 앞) 순으로 노출됩니다. 광고 카드 앞의
손잡이(⠿)를 드래그하거나 ◀▶ 버튼으로 바로 앞/뒤 광고와 순서를 바꿀 수
있습니다 — [[카테고리관리]]/[[메뉴수정품절처리]]에서 쓴 것과 같은
**포인터 이벤트 기반 커스텀 드래그**(손잡이 `pointerdown` → `window`
`pointermove`로 hit-test하며 로컬 재배치 → `pointerup`에 한 번만 저장)
를 그대로 재사용했습니다. `PATCH /api/ads/reorder`가 원하는 순서로
나열한 광고 id 배열을 통째로 받아 배열 인덱스를 그대로 `order` 값으로
저장합니다. 새 광고는 항상 맨 뒤 순서로 추가되고, `order` 필드가 생기기
전에 이미 있던 광고는 서버 시작 시 등록순(`createdAt`)으로 자동
부여합니다(`ensureAdOrder`, 1회성·멱등).

이미지 업로드는 기존 메뉴 이미지 업로드와 동일하게 `POST /api/uploads`
(Cloudflare R2)를 그대로 재사용합니다. 이 김에 상품 전용이던
`uploadProductImage` 함수를 도메인 지식이 없는 `shared/api/uploadImage`
로 옮겨서, 메뉴 이미지와 광고 이미지 업로드가 같은 함수를 씁니다.

관리자 화면에서 "+ 광고 추가"를 누르면 모달(`shared/ui/Modal`)이 뜨고
이미지를 선택해 업로드하면 바로 등록됩니다. 각 광고 카드의 "수정"을
누르면 같은 모달에서 이미지를 다시 선택해 교체할 수 있고, "삭제"는
확인 없이 바로 처리됩니다(광고는 메뉴/카테고리와 달리 삭제돼도 연결된
다른 데이터가 없어 확인창을 넣지 않았습니다).

고객 화면에서는 `AdBanner`가 등록된 광고를 5초마다 자동으로 다음
이미지로 전환하며 보여줍니다(광고가 1개면 전환 없이 고정, 0개면 아예
렌더링하지 않음). **매장/포장 선택 버튼 위에** 배치해 눈에 잘 띄도록
했고, 너비도 모바일/태블릿/데스크탑 화면 너비에 맞춰 커지도록
반응형으로 키웠습니다(`max-w-sm → sm:max-w-xl → md:max-w-2xl →
lg:max-w-4xl`).

이미지는 `object-cover`로 박스를 꽉 채우기 때문에, 박스 가로세로
비율과 실제 업로드한 이미지 비율이 다르면 넘치는 쪽이 잘립니다.
처음엔 화면 너비 구간마다 높이를 독립적인 픽셀값(`h-56 → h-96`
등)으로 따로 지정했는데, 실제 업로드하는 광고 이미지 비율과 맞지
않아 상하단이 잘려나갔습니다 — 한 번은 "키오스크는 세로로 기니까
전체적으로 더 길게" 요청으로 그 높이값들을 전반적으로 키워봤지만,
여전히 너비/높이가 각각 독립적인 값이라 정확히 맞진 않았습니다.
이후 "실제 광고 이미지가 1448×1086(4:3) 비율이니 그에 맞춰달라"는
요청으로, 독립적인 높이값 대신 **`aspect-[4/3]`로 박스 비율 자체를
이미지 원본 비율에 정확히 고정**했습니다 — 화면 너비가 얼마든 높이가
항상 4:3 비율로 따라가므로 크롭이 생기지 않습니다. 다만 이 비율은
지금 등록된 광고 이미지 기준이라, 다른 비율의 이미지를 올리면 다시
잘릴 수 있습니다 — 관리자는 광고를 1448×1086(또는 4:3) 비율로
맞춰 올리는 것을 권장합니다.

**드래그(스와이프)로도 넘길 수 있습니다** — 포인터 이벤트로 좌우 드래그
거리를 재서, 40px 이상 왼쪽으로 밀면 다음, 오른쪽으로 밀면 이전
광고로 넘어갑니다(마우스 드래그·터치 스와이프 모두 동일하게 동작).
자동 전환 타이머는 그대로 유지되므로, 수동으로 넘긴 직후 타이머가
돌면서 한 번 더 넘어갈 수 있습니다(별도 리셋 로직은 없음). 페이지
아래로 스크롤은 막지 않도록 세로 터치 제스처(`touch-pan-y`)는 그대로
허용합니다.

처음엔 이미지 아래에 **흰 배경 띠**를 깔고 그 위에 순서 표시 점을
그렸는데, 이미지와 어울리지 않아 보인다는 피드백으로 **점을 이미지
위에 겹쳐서(반투명 흰색/분홍색 점, `absolute` 배치)** 그리는 방식으로
바꿔 흰 띠를 없앴습니다.

## 관련 코드
- `apps/backend/src/models/Ad.ts` (`imageUrl`, `order`, `timestamps: true`)
- `apps/backend/src/routes/ads.ts` — `GET/POST /api/ads`, `PUT/DELETE
  /api/ads/:id`, `PATCH /api/ads/reorder` (`GET`만 공개, 나머지는
  `requireAdmin`)
- `apps/backend/src/lib/seed.ts` — `ensureAdOrder`(자동 시딩)
- `apps/frontend/src/entities/ad` (`getAds`/`createAd`/`updateAd`/
  `deleteAdById`/`reorderAds`, 고객 화면용 `AdBanner` UI)
- `apps/frontend/src/features/ad-management/model/store.ts`
  (`useAdStore`, `moveAd`/`reorderLocally`/`commitAdOrder`)
- `apps/frontend/src/widgets/manage-ad-list` (관리자 목록 + `AdForm`
  — 추가/수정 겸용, `ad` prop 유무로 구분. 드래그 손잡이 + ◀▶ 순서
  변경 UI)
- `apps/frontend/src/views/admin/ui/AdminPage.tsx` ("광고 관리" 탭)
- `apps/frontend/src/widgets/order-type-select/ui/OrderTypeSelect.tsx`
  (`AdBanner` 배치)
- `apps/frontend/src/shared/api/uploadImage.ts` (상품/광고 공용 이미지
  업로드 — 기존 `entities/product`의 `uploadProductImage`를 여기로 이동)
- `packages/types`의 `Ad`(`order` 필드), `AdInput`, `ReorderAdsInput`
