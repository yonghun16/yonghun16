## 개요
주문 제출이 성공하면 장바구니만 조용히 비워지고 곧바로 매장/포장 선택
화면으로 돌아가던 것과 달리, 이제는 주문번호와 예상 대기 시간을 안내하는
전체 화면이 먼저 뜹니다. 고객이 픽업/서빙을 기다리는 동안의 불확실함을
줄여주고, "주문이 실제로 들어갔다"는 확인감을 줍니다.

## 동작 방식
- `POST /api/orders`가 성공하면 응답으로 받은 `Order`(주문번호 포함)를
  버리지 않고 장바구니 스토어의 `lastCompletedOrder`에 담아둡니다
  (`features/cart/model/store.ts`의 `submitOrder`). 이 필드가 채워져
  있으면 `HomePage`가 매장/포장 선택 화면이나 메뉴 화면 대신
  `OrderCompleteScreen`을 렌더링합니다 — `orderType` 유무를 검사하는
  분기보다 우선순위가 높습니다.
- 화면에는 🎀 안내 문구, 큰 글씨의 `No. {주문번호}`, 매장/포장 여부,
  예상 대기 시간 안내("메뉴 준비까지 약 10~15분 정도 걸려요")가
  나타납니다.
- **예상 대기 시간은 고정 문구입니다.** 실시간 대기열 길이를 계산하는
  방식도 고려했지만, 이 프로젝트는 실제 주방 처리 속도나 동시 주문량
  데이터가 없는 포트폴리오 프로젝트라 대기열 기반 산출은 근거 없는
  숫자를 보여주는 것과 다르지 않다고 판단해 고정값으로 결정했습니다.
  새 API나 백엔드 로직 추가 없이 기존 주문 생성 응답만으로 구현할 수
  있다는 것도 이 선택의 이유입니다.
- "확인" 버튼을 누르거나, 누르지 않아도 8초 뒤 자동으로 화면이 닫힙니다
  (`AUTO_DISMISS_MS`). 닫히면 `lastCompletedOrder`를 비우고
  `resetOrderType()`을 호출해 매장/포장 선택 화면으로 돌아갑니다 —
  기존에 주문 성공 직후 결제 모달에서 바로 호출하던 `resetOrderType()`은
  이 화면의 닫기 동작으로 옮겼습니다.
- 자동 복귀 시점을 [[세션타임아웃]]의 미조작 타이머와 연계할지도
  검토했지만, 이 화면 자체가 8초짜리 독립된 자동 닫힘 타이머를 가지고
  있어 굳이 얽을 필요가 없었습니다.

## 관련 코드
- `apps/frontend/src/widgets/order-complete/ui/OrderCompleteScreen.tsx`
  (`order`, `onDismiss` prop — 주문번호/대기 안내 표시 + 자동/수동 닫기)
- `apps/frontend/src/features/cart/model/store.ts` (`lastCompletedOrder`,
  `clearLastCompletedOrder`, `submitOrder`가 생성된 주문을 저장)
- `apps/frontend/src/views/home/ui/HomePage.tsx` (`lastCompletedOrder`가
  있으면 `OrderCompleteScreen`을 우선 렌더링)
- `apps/frontend/src/widgets/order-summary/ui/OrderSummary.tsx` (주문
  성공 시 결제 모달만 닫고, 매장/포장 선택 화면 복귀는 더 이상 여기서
  하지 않음)
