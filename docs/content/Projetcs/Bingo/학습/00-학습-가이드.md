이 폴더는 "빙고 게임이 왜 이렇게 짜여 있는지"를 이해하고, 나중에 비슷한 실시간 협업 앱을 직접 처음부터 만들 수 있게 되는 걸 목표로 합니다. 다른 곳에서 가져온 일반적인 튜토리얼이 아니라, **이 저장소의 실제 파일과 실제 코드**를 근거로 씁니다.

## 전제 지식
아래를 이미 안다는 가정하에 씁니다. 모른다면 각 항목만 먼저 따로 찾아보고 오는 걸 권장합니다.
- JavaScript/TypeScript 기본 문법 (함수, 타입, 화살표 함수, `?.`/`??` 정도)
- React 컴포넌트와 JSX가 뭔지 (`useState`를 한 번이라도 써본 정도)
- 웹소켓/실시간 통신이 대략 뭘 하는 건지 (자세한 원리는 몰라도 됨 — 02번 문서에서 다룸)

## 학습 순서
1. [[01-리액트-패턴]] — 이 코드에서 반복적으로 나오는 React 패턴(useState vs useRef, useCallback, useMemo, 컴포넌트 분리 기준)을 실제 코드로 익힌다.
2. [[02-Supabase-Realtime-핵심개념]] — Channel / Presence / Broadcast가 뭔지, 이 프로젝트가 그걸로 어떻게 "서버 없는 실시간 동기화"를 만들었는지.
3. [[03-코드-읽는-순서]] — `src/` 전체를 어떤 순서로 읽으면 이해가 되는지 파일 단위로 안내.
4. [[04-핵심-설계-결정]] — 겉보기엔 이상해 보일 수 있는 결정들("왜 굳이 이렇게?")의 이유.
5. [[05-직접-구현해보기]] — 실제로 손을 움직여보는 연습 문제.

## 이 코드가 어떤 문제를 풀고 있는지 (한 문단 요약)
서버(백엔드) 없이, 최대 5명이 브라우저만으로 실시간 빙고 게임을 하려면 "누가 심판을 볼 것인가", "내 보드를 남에게 보여주지 않으면서 어떻게 게임을 진행하는가" 같은 문제가 생깁니다. 이 프로젝트는 Supabase Realtime(Broadcast + Presence)만으로 이 문제들을 풀었습니다. 자세한 배경은 [[게임흐름]](기획 문서)과 `docs/decisions/0001-supabase-realtime-통신.md`(이 결정을 왜 내렸는지 적은 ADR)를 참고하세요.

- `docs/content/specs/001-room-lifecycle` ~ `006-reconnect-sync`: 기능 단위로 쪼갠 LeanSpec 스펙 (`leanspec view 001-room-lifecycle` 등으로 열람)
- `docs/content/기획/게임흐름.md`: 전체 그림을 텍스트+다이어그램으로 정리한 기획 문서
