# 리플 캐리 가산기 (Ripple Carry Adder)

리플 캐리 가산기는 **전가산기를 최하위 비트부터 최상위 비트까지 직렬로 연결한 다비트 덧셈기**입니다. 각 자리의 올림수(캐리)가 물결(ripple)처럼 한 칸씩 위 자리로 전달된다고 해서 이런 이름이 붙었습니다.

## 구조

n비트 덧셈기는 전가산기 n개로 만듭니다.

- 0번 비트(최하위)의 Cin은 0으로 고정합니다.
- i번 전가산기의 Cout이 (i+1)번 전가산기의 Cin으로 연결됩니다.
- 최종 Cout은 n비트 결과를 넘어가는 자리올림으로, 오버플로 판정에 쓰입니다.

## 동작 예시 (4비트: 1011 + 0110)

|비트|A|B|Cin|Sum|Cout|
|:-:|:-:|:-:|:-:|:-:|:-:|
|0|1|0|0|1|0|
|1|1|1|0|0|1|
|2|0|1|1|0|1|
|3|1|0|1|0|1|

결과는 Sum = 0001, 최종 Cout = 1이므로 **10001₂ = 17**입니다. 11 + 6 = 17과 일치합니다.

## 장단점

**장점**

- 구조가 단순하고 설계와 구현이 쉽습니다.
- 전가산기만 반복하면 되므로 면적이 작습니다.

**단점**

- 캐리가 최하위 비트에서 최상위 비트까지 순서대로 전파되어야 합니다. 그래서 지연 시간이 비트 수에 비례해 늘어납니다. 전가산기 하나의 캐리 지연을 t_c라고 하면, n비트 덧셈기의 최악 지연은 대략 n·t_c입니다.
- 64비트처럼 비트 수가 많으면 지연이 커져서 고속 연산에는 적합하지 않습니다.

## 개선 방식

이 지연을 줄이기 위해 실제 프로세서에서는 **캐리 룩어헤드 가산기(Carry Lookahead Adder)** 를 주로 씁니다. 각 자리의 캐리를 입력으로부터 직접 계산해서 캐리 전파를 기다리지 않도록 하는 방식입니다. 그 밖에도 캐리를 블록 단위로 묶는 캐리 셀렉트, 캐리 스킵 방식이 있습니다.

원하시면 4비트 리플 캐리 가산기를 Verilog나 Python으로 구현하는 예제도 만들어 드리겠습니다.
