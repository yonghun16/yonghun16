**solution1(N) 분석**

```
for i = 0 ... i < N * N        // 바깥 루프: N² 번 반복
    for k = 0 ... k <= i        // 안쪽 루프: 최대 i번 반복 (i는 0~N²-1)
        print("Hi")
    for j = N ... j >= 0         // 별개의 루프: N+1번 반복 (i와 무관)
        print("Bye")
```

**바깥 for문**: i가 0부터 N²-1까지 돌아요 → 총 **N² 번** 반복

**k 루프 (i에 종속됨)**: i가 커질수록 k도 최대 i번까지 도니까, i가 0, 1, 2, ..., N²-1일 때 각각 실행 횟수가 늘어나요.

등차수열 합으로 계산하면:
$$0 + 1 + 2 + \cdots + (N^2-1) \approx \frac{(N^2)^2}{2} = \frac{N^4}{2}$$

→ 이 부분만으로도 **O(N⁴)**

**j 루프**: N+1번이라 상수 곱하기 N² 정도 → O(N³) 수준이라 N⁴에 비하면 무시 가능

**전체 solution1의 시간복잡도**: 가장 큰 항인 k 루프가 지배적 → **O(N⁴)**

---

**solution2(N) 분석**

```
for i = 0 ... i < N          // 바깥 루프: N번 반복
    set j = 1
    while j < i               // j가 1에서 시작해서 2배씩 증가
        j *= 2
```

**바깥 for문**: i가 0부터 N-1까지 → **N번** 반복

**while 루프**: j = 1, 2, 4, 8, 16, ... 이렇게 2배씩 커지면서 i보다 작을 때까지 반복해요. "몇 배씩 곱해서 목표값에 도달"하는 패턴은 **로그(log)**의 전형적인 신호예요.

j가 1부터 시작해서 i에 도달하려면 몇 번 곱해야 할까요?

$$2^k \geq i \implies k = \log_2(i)$$

→ while문은 약 **log(i) 번** 반복

**전체 결합**: i가 0부터 N-1까지 도는 동안, 매번 log(i) 번씩 실행되니까:

$$\sum_{i=1}^{N} \log(i) \approx N \log N$$

**전체 solution2의 시간복잡도**: **O(N log N)**

---

**최종 정리**

| 코드 | 시간복잡도 |
|---|---|
| solution1 | **O(N⁴)** |
| solution2 | **O(N log N)** |

**순서대로 고르면**: solution1 = O(N⁴), solution2 = O(N log N) 입니다. N log N이 N⁴보다 훨씬 빠르게(효율적으로) 동작하는 거죠.
