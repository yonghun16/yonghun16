## 개념 정리

**단일 연결 리스트(Singly-LinkedList)** 는 각 노드가 다음 노드만 가리킨다. 뒤로는 갈 수 있지만 앞으로는 못 간다.

**이중 연결 리스트(Doubly-LinkedList)** 는 각 노드가 `next`(다음 노드)와 `prev`(이전 노드)를 모두 가진다. 양방향 순회가 가능하고, 특정 노드를 알고 있으면 그 노드의 삭제를 O(1)에 할 수 있다는 게 핵심 장점이다.

### 노드 구조

```
class Node {
  constructor(value) {
    this.value = value;
    this.next = null;
    this.prev = null;
  }
}
```

### 리스트가 들고 있는 것

- `head`: 첫 번째 노드
- `tail`: 마지막 노드
- `length`: 노드 개수 (관리하면 편함)

### 주요 연산과 시간복잡도

|   |   |   |
|---|---|---|
|연산|이중 연결 리스트|비고|
|head에 추가 (push)|O(1)|prev/next 갱신만 하면 됨|
|tail에 추가 (append)|O(1)|tail 포인터 덕분에 순회 불필요|
|head에서 삭제|O(1)||
|tail에서 삭제|O(1)|단일 연결 리스트는 O(n) — 이전 노드를 찾으려면 처음부터 순회해야 함|
|중간 노드 삭제 (노드를 알고 있을 때)|O(1)|prev.next, next.prev만 이어주면 됨|
|인덱스로 접근|O(n)|배열과 달리 순회 필요|

> 이중 연결 리스트가 단일 연결 리스트보다 나은 지점은 **tail 삭제**와 **역방향 순회**다. 대신 노드마다 포인터 하나(prev)를 더 저장해야 해서 메모리를 더 쓴다.

## 기본 문제

### 1. 단일, 그리고 이중

단일/이중 연결 리스트의 차이점을 묻는 개념 문제다. 핵심은 위 표의 비교를 이해하고 있는지다.

- `prev` 포인터가 있는지 없는지
- 역방향 순회 가능 여부
- 노드 하나당 포인터 개수(1개 vs 2개)

### 2. 이중 연결 리스트

`push`(head 추가), `append`(tail 추가), `insert`(특정 위치 삽입)을 구현하는 기본 문제다.

```javascript
class DoublyLinkedList {
  constructor() {
    this.head = null;
    this.tail = null;
    this.length = 0;
  }

  push(value) {
    const node = new Node(value);
    if (!this.head) {
      this.head = node;
      this.tail = node;
    } else {
      node.next = this.head;
      this.head.prev = node;
      this.head = node;
    }
    this.length++;
    return this;
  }

  append(value) {
    const node = new Node(value);
    if (!this.head) {
      this.head = node;
      this.tail = node;
    } else {
      this.tail.next = node;
      node.prev = this.tail;
      this.tail = node;
    }
    this.length++;
    return this;
  }
}
```

**풀이 포인트**: `push`/`append` 모두 새 노드의 `prev`와 `next`를 양쪽에서 되집어줌으로 연결해줘야 한다. 하나만 연결하면 역방향 순회가 깨진다.

### 3. 정수 명령 처리 8

명령어(예: `1 3` → index 3에 삽입, `2 3` → index 3 삭제 등)를 순차적으로 처리해서 최종 리스트 상태를 출력하는 유형의 문제다.

**풀이 가이드**

1. 명령을 하나씩 파싱해 연산 종류와 인자를 분리한다.
2. 인덱스 접근이 많으면 O(n)이 반복되므로, head/tail 중 가까운 쪽부터 순회하는 것만으로도 큰 최적화가 된다(index < length/2 이면 head에서, 아니면 tail에서 순회).
3. 삽입/삭제 후 `length` 갱신을 명령마다 잊지 말 것.

```javascript
// 예시: index까지 효율적으로 이동
function getNode(list, index) {
  let current;
  if (index < list.length / 2) {
    current = list.head;
    for (let i = 0; i < index; i++) current = current.next;
  } else {
    current = list.tail;
    for (let i = list.length - 1; i > index; i--) current = current.prev;
  }
  return current;
}
```

## 연습 문제

### 1. 노드의 관계

주어진 노드의 `prev`, `next`를 따라가며 주변 노드와의 관계(형제, 부모-자식이 아니라 수평적인 이웃 관계)를 파악하는 문제다. `node.prev.next === node`, `node.next.prev === node` 가 항상 성립해야 한다는 건 이중 연결 리스트의 핵심 불변식이다.

### 2. 특이한 삭제

일반적인 중간 노드 삭제와 달리 head/tail이거나 노드가 하나뿐인 경우 등 **엣지 케이스**를 다루는 문제다.

**주의할 엣지 케이스**

- 노드가 1개뿐일 때 삭제 → head와 tail을 모두 null로
- 삭제할 노드가 head일 때 → `prev`가 없으므로 새 head의 `prev`를 null로
- 삭제할 노드가 tail일 때 → 새 tail의 `next`를 null로

```javascript
function removeNode(list, node) {
  if (node.prev) node.prev.next = node.next;
  else list.head = node.next; // node가 head였던 경우

  if (node.next) node.next.prev = node.prev;
  else list.tail = node.prev; // node가 tail이었던 경우

  node.next = null;
  node.prev = null;
  list.length--;
  return node;
}
```

### 3. head로부터의 삭제 메서드

head만 받아 리스트의 첫 번째 노드를 제거하는 메서드를 구현하는 문제다.

```javascript
removeFromHead() {
  if (!this.head) return null; // 빈 리스트

  const removed = this.head;

  if (this.head === this.tail) {
    // 노드가 하나뿐일 때
    this.head = null;
    this.tail = null;
  } else {
    this.head = this.head.next;
    this.head.prev = null;
  }

  removed.next = null;
  this.length--;
  return removed;
}
```

**풀이 포인트**: 노드가 하나뿐인 경우를 따로 분기하지 않으면 `this.head.prev = null` 에서 `this.head` 가 null이되어 오류가 난다.

## 테스트 문제

### 1. tail로부터의 삭제 메서드

head와 대칭되는 문제로, tail을 받아 리스트의 마지막 노드를 제거하는 메서드를 구현한다.

```javascript
removeFromTail() {
  if (!this.tail) return null; // 빈 리스트

  const removed = this.tail;

  if (this.head === this.tail) {
    // 노드가 하나뿐일 때
    this.head = null;
    this.tail = null;
  } else {
    this.tail = this.tail.prev;
    this.tail.next = null;
  }

  removed.prev = null;
  this.length--;
  return removed;
}
```

**풀이 포인트**

- head 삭제 메서드와 구조가 대칭되지만 `next`와 `prev`의 역할이 서로 바뀜 점에 유의한다.
- 노드가 하나뿐인 경우를 먼저 처리해야 `this.tail = this.tail.prev` 에서 예외가 나지 않는다.
- 삭제된 노드의 `prev`를 null로 끓어주어 메모리 누수를 막는다.

## 학습 팁 및 자주 하는 실수

- **prev/next 둘 다 업데이트**: 하나만 연결하고 놓치는 가장 흔한 실수다. 노드를 삽입/삭제할 때마다 양쪽 포인터를 모두 점검하는 습관을 들이자.
- **head/tail 경계 처리**: 노드가 0개·1개일 때를 항상 따로 테스트하자. 이 문제에서 가장 많은 에러가 발생한다.
- **삭제된 노드의 포인터 정리**: `next`/`prev`를 null로 끔어주지 않으면 메모리 누수로 이어질 수 있다.
- **length 갱신 누락**: 삽입/삭제 후 `length++`/`length--`를 잊으면 이후 인덱스 기반 최적화(getNode 등)가 엇나간다.
- **head와 tail 메서드는 대칭 구조**: 하나를 구현하고 나면 반대쪽(head↔tail, next↔prev)을 뒤집어 다른 하나를 만들면 실수를 줄일 수 있다.
